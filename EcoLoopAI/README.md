# EcoLoop AI 2.0

Готовий статичний PWA з камерою, екожурналом, масою, статистикою, редагуванням, фільтрами, CSV і резервними копіями. Інтерфейс українською. Матеріал користувач визначає за маркуванням і обирає вручну.

## Перше встановлення цієї версії

1. Розпакуйте архів. Замініть попередні файли проєкту цим комплектом.
2. Завантажте весь вміст папки в корінь того самого репозиторію GitHub одним commit. `index.html` має лежати безпосередньо в корені, поруч із `app.js` та `sw.js`. Папку `icons` завантажте разом із PNG-файлами. Python на сервері не потрібен.
3. Дочекайтеся успішної публікації в GitHub Actions.
4. На телефоні відкрийте адресу `update.html` у вашому проєкті. Наприклад, до адреси `https://ВАШ_ЛОГІН.github.io/EcoLoopAI/` додайте `update.html`.
5. Натисніть «Завантажити оновлення». Сторінка завантажить файли й відкриє застосунок.
6. Порівняйте короткий номер версії внизу сторінки на ноутбуці та телефоні.
7. Перевірте перший запис, камеру й очищення фото після збереження. Один раз відкрийте застосунок з інтернетом і дочекайтеся завершення завантаження. Потім перевірте повторне відкриття в режимі польоту.

## Локальний запуск

У терміналі в цій папці:

```powershell
py -m http.server 8000
```

Відкрийте `http://localhost:8000/`. Для встановленого PWA на телефоні використовуйте HTTPS-адресу GitHub Pages.

## Як публікувати наступні зміни

Після редагування файлів запустіть:

```powershell
py build.py
```

Скрипт використовує стандартну бібліотеку Python. Він сам обчислює номер випуску за вмістом, оновлює посилання на JS/CSS, `sw.js` і `version.json`. Запуск без змін створює той самий номер.

Завантажте вміст папки на GitHub одним commit. У застосунку натисніть «Перевірити оновлення», потім «Оновити». Підтвердіть очищення форми, якщо є незбережений запис. На час оновлення потрібен інтернет.

Сторінка `update.html` доступна також за посиланням «Відновити оновлення» внизу застосунку. Вона допомагає перейти зі старих варіантів service worker, у яких ще не було кнопки оновлення.

## Дані

- Записи зберігаються в IndexedDB на цьому пристрої для поточного домену й папки застосунку.
- Під час першого запуску переноситься попередня історія з ключа `ecoloop-sorting-history-v1` у localStorage. Для цього відкривайте той самий домен і шлях GitHub Pages у тому самому браузері. Приватна вкладка має окремі дані.
- Старі записи мають стан «Відсортовано» й масу «Без зважування». Можна відредагувати їх і вказати масу.
- Маса необов’язкова. Точність становить 1 грам. Для дробових чисел підтримуються крапка й кома.
- Статус «Передано» є позначкою самого користувача. Підтвердження від пункту приймання потребує окремої серверної частини.
- Фото показується у формі й очищається після успішного збереження. Воно не входить до історії та резервної копії.
- CSV містить усю історію. Кодування UTF-8, роздільник `;`, дата в UTC. Якщо Excel показує один стовпець, імпортуйте через «Дані → З тексту/CSV» з роздільником «крапка з комою».
- Резервна копія JSON придатна для перенесення на інший телефон. Імпорт додає відсутні записи й пропускає наявні з тими самими ID. Для перенесення правок уже наявного запису редагуйте його на потрібному пристрої.
- Журнали різних пристроїв синхронізуються через експорт та імпорт резервної копії. Оновлення сайту змінює файли програми, журнал зберігається в окремій базі.

## Файли

| Файл | Призначення |
| --- | --- |
| `index.html` | Усі елементи інтерфейсу |
| `style.css` | Адаптивне оформлення |
| `app.js` | Фото, форма, статистика, історія, імпорт, експорт і кнопка оновлення |
| `store.js` | База записів, транзакції, перенесення старої історії |
| `sw.js` | Версійований офлайн-кеш і активація оновлення |
| `version.json` | Номер опублікованого випуску, створюється `build.py` |
| `update.html` | Самодостатня сторінка переходу зі старого кешу |
| `manifest.webmanifest` | Встановлення на домашній екран |
| `icons/` | Іконки застосунку |
| `build.py` | Підготовка випуску перед публікацією |

## Перевірка комплекту

У Chromium перевірено перенесення старої історії, збереження й очищення фото, масу з комою та крапкою, редагування, фільтри, видалення і повернення, CSV, резервну копію, повторний та некоректний імпорт, одночасну роботу вкладок, офлайн-запуск, перехід між випусками та відновлення після старого cache-first service worker. Перевірено ширину екрана 320, 390 і 1280 px. Якщо бракує файла нового випуску, попередній офлайн-кеш продовжує працювати.

Фізичні Android/iPhone і фактична камера користувача потребують перевірки після публікації на його GitHub Pages.
